## 🧩 Publisher

**Publisher** is the middleware layer that connects the **Gateway Server** to the **RelaySMS (SMSWithoutBorders) backend**.  
It plays a critical role in securely relaying and translating user intentions—sent via SMS—into valid, authenticated requests to online platforms like Gmail, Twitter, and Telegram.

---

### 🔄 What Does Publisher Do?

The Publisher acts as a **secure interpreter** and **executor**:

1. ✅ Receives SMS-based command payloads from the Gateway Server
2. 🤝 Performs a secure handshake with the backend to validate the request
3. 🔐 Decrypts the OAuth2 tokens stored in encrypted Vaults
4. 📡 Uses the decrypted tokens to make authorized API calls on behalf of the user
5. 📥 Returns the response to be sent back via SMS through the gateway

This makes it possible for users with **no internet connection** to interact with cloud-based platforms **using only SMS**.

---

### 🚀 Use Case: Publishing via SMS

A user without internet sends an SMS formatted command to a gateway client.  
That SMS reaches the Publisher, which:

- Authenticates the user via token signature
- Decrypts their token from a secure vault
- Sends the command (e.g., "Tweet this text" or "Send Gmail") to the respective platform
- Retrieves the response (e.g., “Tweet posted!”)
- Sends it back to the user via SMS

All of this happens within seconds, transparently and securely.

---

### 🔐 Security & Trust

Publisher enforces:

- **Vault-Based Token Storage**: OAuth2 tokens are never exposed; they are encrypted at rest.
- **Request Signing & Verification**: All commands are signed and validated to prevent spoofing.
- **Least Privilege**: Requests are made only with the minimum required scopes.
